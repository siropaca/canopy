# ADR-0019: ドラッグ並び替えは dnd-kit を使わず、仮想リストのインデックスで自前で書く

- ステータス: 採用
- 日付: 2026-08-21

> [ADR-0012](0012-scrollbar-and-virtualization.md) の「ドラッグ並び替え」だけを置き換える。
> スクロールバーと仮想化の決定はそのまま生きている。

## 背景

ADR-0012 は並び替えに `@dnd-kit/core` + `@dnd-kit/sortable` を使うと決めた。  
同じ ADR で「ドロップ位置は行の DOM ではなく**仮想化リストのインデックス**から決める」とも決めている。

フェーズ 3 で実装に入る段になって、この 2 つが噛み合わないことが分かった。

dnd-kit の衝突判定は、登録済みの droppable が報告する**矩形**を突き合わせて動く。  
矩形は DOM から測るので、仮想化で画面外の行が消えると droppable も消える。  
つまり dnd-kit に任せると「画面に出ているリポジトリにしかドロップできない」形になり、ADR-0012 が避けたかった状態そのものになる。

回避するには、`useDroppable` を使わずにポインタの Y 座標からインデックスを計算して、その結果を dnd-kit の状態に流し込むことになる。  
それは「位置を決める部分は自前で書き、ライブラリは持ち歩きだけ担当する」形で、依存を入れる理由が薄い。

もう 1 つ、v1 の並び替えの要件はかなり狭い。

- 動かせるのはリポジトリ見出しだけ。ブランチ行は動かせない
- 並べ替える対象は `RepoId` の配列 1 本
- 挿入線は行ではなく**リポジトリのブロック境界**に描く (展開中なら配下の行の後ろ)
- キーボード操作は持たない ([ADR-0008](0008-no-keyboard-shortcuts.md))

dnd-kit の主機能 (キーボードセンサー、複数コンテナ、任意の並べ替え戦略) は、どれも v1 では使わない。

## 決定

- **`@dnd-kit/*` を追加しない。** 並び替えは自前で書く
- ドラッグの追従は `pointerdown` / `pointermove` / `pointerup` で行う。しきい値 (4px) を超えるまでは選択として扱う
- ドロップ位置は**行の配列のインデックス**から決める。ポインタの Y からビューポート内の位置を出し、行高で割って行インデックスにする。DOM のヒットテスト (`elementFromPoint` / `closest`) は使わない
- 行インデックスは**リポジトリのブロック境界**に丸める。ブロックはその見出し行から次の見出し行の直前まで。挿入位置は「何番目のリポジトリの前か」で持つ
- 端でのオートスクロールは、ビューポートの上下 24px にポインタが入っているあいだ `requestAnimationFrame` で `scrollTop` を動かす
- 並び替えの計算 (`RepoId[]` と挿入位置から次の並びを作る) は `shared/lib/reorder.ts` に純粋関数として置く。React にもポインタにも依存させない
- Esc とウィンドウ外への `pointercancel` で取り消す。取り消したら並びは変えない

## 理由

- ADR-0012 が決めた「インデックスから決める」を満たすなら、dnd-kit の衝突判定は使わないことになる。使わない機能のために依存を 2 つ増やさない
- 位置の計算が自前になるぶん、**ユニットテストで固定できる**。`RowNode[]` と行インデックスを渡して並びと挿入位置を検査する形にできる。DOM の矩形に依存すると jsdom では検査できない
- 残るのはオートスクロールとキャンセル処理だけで、どちらも数十行に収まる。ADR-0012 が「自前で書くと必ず粗が出る」と書いたのは、衝突判定まで自前で持つ前提だった
- 依存が減ると、フェーズ 4 のビルドとバンドルの検証が軽くなる

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| ADR-0012 どおり dnd-kit を使う | 衝突判定が DOM 矩形なので、仮想化で画面外のリポジトリがドロップ先にならない。位置決めを自前にすると、残るのは持ち歩きだけになる |
| dnd-kit を使い、ツリーの仮想化をやめる | 仮想化は ADR-0012 の決定。並び替えのために全件描画へ戻さない |
| ドラッグ中だけ全リポジトリを畳む | 畳むと折りたたみ状態を書き換える。検索中は畳めないので、条件によって挙動が変わる |
| HTML5 の Drag and Drop API (モックの実装) | `dragover` の対象が DOM の行なので、画面外へはドロップできない。ドラッグ画像の見た目も制御しにくい |
| 並び替え専用の別画面を作る | 並び替えのためだけに画面を増やす (ADR-0012 と同じ理由で却下) |

## 影響

- 依存は増えない。フェーズ 1 で `@dnd-kit/*` を入れていなかった状態のままでよい
- ドロップ位置の計算は行高が一定であることに依存する。ツリーの行高を可変にするなら、この計算を測定ベースに変える必要がある
- 仮想リスト側にスクロール要素を外へ渡す口が要る (自前スクロールバーのビューポート)。すでに `ScrollArea` の `onViewport` がある
- キーボードでの並び替えは持たない。キーボード操作を入れるなら ADR-0008 ごと見直す
