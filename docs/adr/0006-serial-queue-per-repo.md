# ADR-0006: git の書き込みはリポジトリごとに直列化する

- ステータス: 置き換え済み ([ADR-0009](0009-concurrency-and-refresh.md))
- 日付: 2026-08-21

> 「リポジトリごとに直列、リポジトリ間は並列」という核は ADR-0009 でも維持している。  
> 置き換えたのは「読み取りはキューを通さなくてよい」という部分と、未定義だった並行モデル。

## 背景

全リポジトリを一括でフェッチする機能がある。  
同じリポジトリに対して git を同時に走らせると `index.lock` が競合して失敗する。

## 決定

リポジトリごとに実行キューを持ち、そのリポジトリの書き込み操作を直列に流す。  
異なるリポジトリの操作は並列に実行する。同時実行数には上限を設ける。

## 理由

- ロックの競合を、待たせるだけで確実に避けられる
- 一括フェッチは並列でないと待ち時間が現実的でない
- 読み取り (`for-each-ref` など) は `GIT_OPTIONAL_LOCKS=0` を付ければロックを取らないので、キューを通さなくてよい

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| 全体で 1 本の直列キュー | 一括フェッチが遅すぎる |
| 失敗したらリトライする | 競合の原因を残したまま隠すことになる |

## 影響

- キューの状態は UI に出す余地がある (実行中の表示は v1 では持たない)
- 同じリポジトリに操作を続けて投げたときの順序は、投入順になることを保証する
- キューはテストしやすい単位として切り出す
