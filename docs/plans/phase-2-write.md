# フェーズ 2: 操作

## 目的

チェックアウト・フェッチ・プル・プッシュ・名前の変更ができる状態にする。  
失敗も正しく失敗として見える。

## やること

### Rust 側

- [ ] 直列実行キューを作る。**キーは `git rev-parse --git-common-dir` の実パス。** リポジトリ id ではない (ワークツリーが ref store を共有するため)
- [ ] 同一リポジトリ内は書き込み排他・読み取り共有にする
- [ ] ネットワーク操作に 30 秒のタイムアウトと kill を入れる。`GIT_SSH_COMMAND` に `ConnectTimeout=5` を渡す
- [ ] 同種操作の重複排除。フェッチ連打で 11 本積まれないようにする
- [ ] 意図ごとの Tauri コマンドを作る。汎用の実行コマンドは作らない
- [ ] **すべての参照引数**を通す共通の検証関数を作る。名前変更だけではない
- [ ] 検証は `git check-ref-format --branch <名前>` で行う。加えて `-` 始まり・`@{` を含む・`..` を含む名前を明示的に拒否する
- [ ] 参照の切り替えは `git switch` を使う。`--end-of-options` を挟む ([../security.md](../security.md))
- [ ] git の非ゼロ終了は `Ok(CommandResult{ok:false})` で返す。`Err` はアプリ側の異常だけ
- [ ] 操作の戻り値は `{ result, snapshot }` の 1 つにまとめる。フロントが 2 回 invoke する形にしない
- [ ] よくある失敗を判定して文言を付ける ([../specs/git-operations.md](../specs/git-operations.md) の表)。**判定は「操作の種別 × 出力」で行う。** 同じ `(non-fast-forward)` がプルとプッシュで逆の意味になる
- [ ] リモートブランチのチェックアウトは、ローカルに同名があるかで分岐する。無ければ `git switch -c --track`、有れば既存に切り替えた旨を返す
- [ ] 強制プッシュは `--force-with-lease=<名前>:<sha>` で sha を明示する
- [ ] 名前変更のあとに `git branch --unset-upstream` を実行する。`-m` は追跡先を旧名のまま残す
- [ ] **成否に関係なく**対象リポジトリのスナップショットを取り直して返す。書き込みと同じ直列区間の中で行う
- [ ] キューは `tokio::sync::Mutex` (リポジトリごと) + `tokio::sync::Semaphore` (全体) で書く

### フロント側

- [ ] コンテキストメニュー。行の種類でメニューを出し分ける。括り行とディレクトリでは出さない
- [ ] v2 の項目をグレーで置く。押しても何も起きない
- [ ] ダイアログの共通の枠を作る
- [ ] ブランチ名の変更ダイアログ
- [ ] プッシュダイアログ。コミット一覧、強制プッシュのチェック、ボタンの色と文言の変化
- [ ] 詳細ペインのボタンを動かす
- [ ] サイドバーのフェッチとプルを動かす。選択に応じた有効・無効
- [ ] ダブルクリックでチェックアウト
- [ ] 実行中はそのリポジトリの操作系 UI を無効にする。行を薄くする。スピナーは出さない
- [ ] detached HEAD から戻る「直前のブランチに戻る」を入れる
- [ ] `⧉` が付いたブランチのチェックアウトを無効にする (必ず `already used by worktree at` で失敗するため)
- [ ] `⧉` が付いたブランチのプルは、そのワークツリーで実行する
- [ ] `gone` が付いたブランチのプルを無効にする
- [ ] 強制プッシュのチェックボックスは ahead が 0 のとき無効にする。behind だけのブランチに撃つとリモートを巻き戻す


## フェーズ 1 のレビューから持ち越した設計課題

書き込みのコマンドを足すときに、先にこれを片付ける。

- [ ] **並行制御の合成を 1 箇所に出す。** いまは `get_repo_snapshot` が
      「locate → 読み取りの permit → revision の採番 → build_snapshot」の順序を直接持っている。
      書き込みが 6〜7 本乗ると「locate → 書き込みロック → 参照名の検証 → git → **同じロックの中で**
      取り直し → `{result, snapshot}`」が各コマンドに複製される。
      `&AppState` を受ける関数に落とせば、順序を守っていることをユニットテストで固定できる
      (`AppState::load(path)` は Tauri 無しで作れる)
- [ ] **`commands/repo.rs` を分ける。** いまは設定の CRUD・追加フロー・スナップショット読みの 3 役。
      操作系を足す前に `commands/settings.rs` / `commands/snapshot.rs` / `commands/ops.rs` へ分けると、
      `generate_handler!` のパス書き換えが 1 回で済む
- [ ] **行の述語を `shared/lib/selection.ts` に集める。** `⧉` 付きはチェックアウト無効、
      `gone` はプル無効、ahead 0 なら強制プッシュ無効、実行中はそのリポジトリの操作系すべて無効。
      サイドバー・コンテキストメニュー・詳細ペインの 3 features が同じ入力から判断するので、
      features には置かない (フェーズ 1 で `canPullSelection` / `isFoldable` を置いた場所)
- [ ] **「画面に見えている選択」を `store/useSelectedRow.ts` に出す。** いまは `app/App.tsx` が
      `rows.find` で解いて props で配っている。コンテキストメニューとダイアログが同じものを要る
- [ ] **`RepoState` に「実行中」が増えたときの参照経路を 1 本にする。** 正はストア側
      (`src/ipc/types.ts` の `RepoRow` に注記済み)

## テスト

| 層 | 内容 |
| --- | --- |
| Rust ユニット | コマンド組み立て。参照名の検証。`-` 始まりや空白入りの名前を弾くこと |
| Rust ユニット | キュー。同一リポジトリが直列になること、異なるリポジトリが並列になること、投入順が保たれること |
| Rust 統合 | 未コミットがある状態でプルして失敗すること。behind がある状態でプッシュが拒否されること |
| Rust 統合 | 他のローカルブランチのプル (`fetch origin x:x`) が、早送りできないときに失敗すること |
| Rust ユニット | `checkout_branch(id, "-f")` のような引数が検証で弾かれること |
| Rust 統合 | チェックアウト、フェッチ、名前の変更が成功して状態が変わること |
| フロント ユニット | 行の種類からメニュー項目を決める関数 |
| コンポーネント | ダイアログの状態遷移。強制プッシュでボタンが変わること |

**破壊的な操作をテストするので、必ず一時リポジトリに対して実行する。**  
ユーザーの実リポジトリを対象にしたテストを書かない。

## 完了条件

- [ ] 一時リポジトリに対して 5 つの操作すべてが成功する
- [ ] [../specs/git-operations.md](../specs/git-operations.md) の失敗表の全項目が、想定した文言で表示される
- [ ] プルの失敗にプッシュの文言が出ない (`(non-fast-forward)` の出し分け)
- [ ] 同一リポジトリに操作を連続で投げても `index.lock` の失敗が出ない
- [ ] 一括フェッチ中でもチェックアウトが待たされずに実行できる
- [ ] `git checkout X && git pull --rebase` の後半が失敗したとき、画面が X に切り替わっている
