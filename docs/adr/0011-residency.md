# ADR-0011: 常駐と前面化

- ステータス: 採用
- 日付: 2026-08-21

## 背景

ADR-0001 が Tauri を選んだ唯一の理由は「常時起動しておいて、必要なときにすぐ前面に出せる」こと。  
しかしどう常駐してどう前面に出すかが、どこにも書かれていなかった。

素直に作るとウィンドウを閉じた時点でプロセスが終了し、起こし直すたびに全リポジトリの読み込みを払う。  
選定理由が実装に反映されないまま終わる。

## 決定

- ウィンドウを閉じてもプロセスは終了しない。ウィンドウを隠す
- メニューバーのアイコンから復帰する
- 二重起動を防ぐ。2 個目の起動は既存のウィンドウを前面に出す (`tauri-plugin-single-instance`)
- ウィンドウの位置とサイズを保存して復元する。保存先はアプリ自身の設定ファイル ([ADR-0016](0016-store-without-plugin.md) の設定ファイル) に寄せる
- グローバルショートカットは v1 では持たない。[ADR-0008](0008-no-keyboard-shortcuts.md) の「キーボード操作を持たない」はアプリ内の操作についての判断で、前面化のショートカットは別問題として v2 で検討する

## 理由

- 常駐しないなら Tauri を選んだ意味が薄い
- 二重起動を許すと、2 つのプロセスが同じ設定ファイルを書く。デバウンス保存と重なると後から書いた方が相手の変更を消す
- ウィンドウ状態を plugin 専用ファイルに持つと保存先が 2 箇所になり、ADR-0005 の「中身を直接読める」が半分崩れる

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| 通常のアプリとして毎回起動する | 起動のたびに読み込みを払う。常駐を選定理由にした前提と合わない |
| メニューバー常駐のみ (ウィンドウを持たない) | 表示領域が足りない。ツリーと詳細の 2 ペインが入らない |
| `tauri-plugin-window-state` を使う | 設定の保存先が 2 箇所になる |

## 影響

- 終了する手段を明示的に用意する必要がある (メニューバーのメニューに「終了」)
- 常駐中のメモリ使用量が問題になる。ADR-0001 の目標値として測る対象にする
- 隠れている間もフェッチを走らせるかは v1 では決めない。手動フェッチのみ
