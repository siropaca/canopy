# ADR-0008: v1 はキーボード操作を持たない

- ステータス: 採用
- 日付: 2026-08-21

## 背景

モックでキーボード操作 (矢印での移動、Enter でチェックアウト、⌘R でフェッチ) を試したが、外した。

## 決定

v1 はマウス操作だけで完結させる。  
ショートカットは実装せず、メニューにも表示しない。  
例外はダイアログ内の Enter (確定) と Esc (キャンセル) だけ。

## 理由

- **誤爆で git が走るのが一番まずい。** ツリーにフォーカスがある状態で Enter を押してチェックアウトが走ると、作業中の変更を巻き込む
- ショートカットの体系を設計するには、まず操作の全体像が固まっている必要がある。v1 の段階では動く土台がない
- ショートカットの表示があると「押せる」と思わせてしまう。無いなら見せない方が誤解が少ない

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| 移動だけ許して実行系を持たない | 中途半端で、結局 Enter を押したくなる |
| 危険な操作に確認を入れて許す | 確認ダイアログが増えて、マウス操作の体験まで悪くなる |

## 影響

- アクセシビリティは犠牲にしている。個人ツールとして意図的に割り切った判断
- v2 で入れるときは、実行系と移動系を分けて、実行系には確認を挟むところから設計する
- ツリーは `tabindex` を持ちフォーカスは受ける。選択色をフォーカス状態で変えるため
