# ADR-0003: 状態は Zustand、スタイルは CSS Modules + トークン

- ステータス: 採用
- 日付: 2026-08-21

> **既知の逸脱。** この ADR は状態管理とスタイルという独立した 2 つの判断を含んでいる。  
> [README](README.md) の「1 ファイル 1 判断」に反しているが、分割の実利が薄いので承知の上で残す。  
> どちらか一方を見直すときは、その判断だけを新しい ADR にして、ここには触れない。

## 背景

画面は 1 つで、状態は「リポジトリのスナップショット」と「UI の状態」に分かれる。  
UI は IDEA を模した高密度な独自デザインで、既製のコンポーネントは使わない。

## 決定

状態管理は Zustand。  
スタイルは CSS Modules + CSS 変数のトークン。

## 理由

- 状態は素朴。Redux のような仕組みは要らない。Context だけだと再描画の制御が面倒
- モックが CSS 変数でトークンを持っているので、そのまま移せる。値の一致をテストで縛れる
- Tailwind は既製のスケール (色・余白) に寄せる道具で、IDEA の 1px 単位の密度を再現するには噛み合わない
- CSS Modules はコンポーネントとファイルが 1:1 になり、消し忘れが起きにくい

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| Redux Toolkit | この規模では過剰 |
| Tailwind CSS | 独自の密度とトークンを再現するのに逆らう形になる |
| CSS-in-JS | 実行時コストと、モックからの移植のしやすさで劣る |

## 影響

- トークンは `src/shared/styles/tokens.css` に置き、モックと一致していることをテストで確認する
- グローバル CSS はリセットとトークンだけ。それ以外は必ず Modules にする
