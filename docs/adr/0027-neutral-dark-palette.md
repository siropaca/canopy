# ADR-0027: 面と文字の色を青みのないグレーに揃える

- ステータス: 採用
- 日付: 2026-09-30

## 背景

色は IntelliJ IDEA の新 UI (ダークテーマ) に寄せていた ([../design-system.md](../design-system.md))。  
面は青みのあるグレー (`#1e1f22` / `#2b2d30`) で、フォーカスのある選択とプライマリボタンは青。  

普段は Orca と並べて使っている。  
Orca のダークテーマは青みのないグレー (背景 `#0a0a0a`、サイドバー `#171717`) で、選択にもボタンにも青を使わない。  
並べると Canopy だけ色味が浮くので、Orca に揃えたいという要望が出た。

## 決定

**面・境界・文字・選択・ボタンを Orca のダークテーマの値に寄せる。意味の色と見出しの色は変えない。**

- 面は `#0a0a0a` (背景) / `#171717` (サイドバー・メニュー・ダイアログ) / `#262626` (リポジトリ見出し) の 3 段
- 文字は `#fafafa` (本文) / `#a1a1a1` (補助) / `#737373` (件数など) / `#525252` (無効)
- 選択はフォーカスの有無にかかわらずグレー。フォーカスがあると明るくする (`#404040`、なしは `#2e2e2e`)
- プライマリボタンは明るいグレーの地 (`#e5e5e5`) に濃い文字。上に乗せる文字色は `--accent-fg` として足す
- 入力欄のフォーカスはグレー (`#737373`) の枠。`--ring` として足す。検索欄とダイアログの入力欄の両方に使う
- behind の青・ahead の緑・未コミットのオレンジ・ワークツリーの紫、見出しの 6 色、削除と失敗の赤はそのまま残す

値は Orca のアプリに入っている CSS から取った。  
Orca の境界線は白の 7% の半透明だが、Canopy では下の面によって色が変わらないよう不透明の値にしている。

## 理由

- 画面の中に青が残るのが意味の色だけになり、behind やリンクの青がはっきり目立つ
- キーボード操作を持たない ([0008-no-keyboard-shortcuts.md](0008-no-keyboard-shortcuts.md)) ので、選択のフォーカスの有無を色相で強く見分ける必要がない
- ほとんどはトークンの値を変えるだけで済む。コンポーネントの CSS で差し替えるのは、プライマリボタンとトーストのアイコンの文字色 (`--accent-fg`) と、入力欄のフォーカスの枠 (`--ring`) だけ

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| 意味の色も Orca の git の色 (追加 `#81b88b`、変更 `#e2c08d` など) に揃える | Orca には behind・ahead・ワークツリーにあたる色が無く、結局そこは自分で決めることになる。彩度が下がってインジケーターが目立たなくなる |
| フォーカスのある選択だけ青を残し、暗い背景に合わせて沈める | 今の仕様は変えずに済むが、画面の中で青い帯だけが浮いて Orca と揃わない |
| プライマリボタンは Orca に合わせ、入力欄のフォーカスは青のまま | 入力欄のフォーカスは分かりやすいが、見た目の方針が半分ずつ混ざる |
| ボタンもフォーカスも青のまま | 背景がグレーになるぶん、青いボタンが今より浮く |

## 影響

- `--accent-fg` と `--ring` の 2 つのトークンが増える
- プライマリの指定は、通常のボタンの指定より特異性を高くしておく必要がある。負けると明るい地に通常の文字色 (`--fg`) が乗って読めない ([../pitfalls.md](../pitfalls.md))
- リポジトリ見出しの選択 (フォーカスあり) は、見出しの 6 色のどれよりも明るいグレーにする。暗いと色付きの見出しと見分けられない
- プライマリの地が明るくなったので、無効なときに地を外す決まり ([../pitfalls.md](../pitfalls.md)) は引き続き要る。明るい地に `--disabled` の文字を乗せても読めない
- README のスクリーンショットは古い色のまま残る。撮り直すまでは実際の画面と色が違う
- Orca の配色が大きく変わったら見直す
