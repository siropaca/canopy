# ADR を書く

## いつ書くか

**実装より先。**  
「決めたから書く」のであって「実装したから記録する」のではない。

書く対象は、後から「なぜこうなっているのか」を聞かれる判断。

- 依存を追加した / 使わないことにした
- データの持ち方、レイヤの切り方を決めた
- 性能や安全のために制約を入れた
- スコープを削った

書かない対象は、変数名やファイル配置のような、コードを読めば分かること。

## 手順

1. 次の番号を確認する

```sh
ls docs/adr/ | grep -E '^[0-9]{4}' | tail -1
```

2. `docs/adr/template.md` をコピーして `docs/adr/<番号>-<英小文字のスラッグ>.md` を作る
3. 埋める。**「検討した他の案」を空にしない。** 比較していない判断は判断ではない
4. `docs/adr/README.md` の一覧に行を足す
5. 関連する docs からリンクする

## 判断が変わったとき

既存の ADR を書き換えない。

1. 新しい ADR を書く。背景に「ADR-XXXX を見直す理由」を書く
2. 古い ADR のステータスを `置き換え済み (ADR-YYYY)` にする
3. 一覧の表も両方更新する

判断の履歴が残ることに価値がある。  
上書きすると「なぜ前はそうしなかったのか」が失われる。
