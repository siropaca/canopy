# ADR-0016: 設定は store プラグインを使わず自分で読み書きする

- ステータス: 採用
- 日付: 2026-08-21
- [ADR-0005](0005-persistence.md) を置き換える

## 背景

ADR-0005 は「Tauri の store プラグインで JSON ファイルに保存する」と決めた。  
フェーズ 1 で実際に書き始めたところ、保存する中身が次の 3 つだと分かった。

- リポジトリの id とパスの対応
- 並び順
- `UiState` ([../specs/data-model.md](../specs/data-model.md))

このうち id とパスの対応は、**フロントに渡してはいけない情報**を含む。  
[../security.md](../security.md) の不変条件は「git を実行する対象はコマンド引数の id からのみ解決する」で、  
id からパスを引ける表を持つのは Rust 側だけ。

store プラグインはフロントから同じファイルを読み書きできるようにするためのものなので、  
この不変条件と目的が逆を向いている。

加えて、id の発行・重複判定・並び順の書き換えはユニットテストで固めたい部分だが、  
プラグインの API は `AppHandle` を要求するので、テストが Tauri のモックを立てる話になる。

## 決定

`serde_json` で自分で読み書きする。  
保存先は `AppHandle::path().app_config_dir()` の下の `canopy.json`。

- 読み書きするのは Rust 側だけ。フロントが**設定ファイルを直接開く口は作らない**
- 保存する構造体は `AppHandle` を知らない素の struct にして、`load(path)` / `save(path)` を持たせる
- スキーマに `version` を持たせる (ADR-0005 の「影響」を引き継ぐ)
- 保存はまとめて行う (デバウンス)。これも ADR-0005 から引き継ぐ

ADR-0005 の「JSON ファイルに保存する」という判断そのものは変えない。  
変えるのは手段だけ。

> 実装時の補足 (2026-08-21)。  
> 設定ファイルを読み書きするコマンドは `get_ui_state` / `save_ui_state` だけではない。  
> `list_repos` / `add_repo` / `remove_repo` も同じ `canopy.json` を触る。  
> 制約は「口の数」ではなく「**ファイルを開くのは Rust 側だけ**」で、フロントには id と `UiState` しか渡さない。

## 理由

- 依存が増えない。`serde_json` はすでに DTO で使っている
- フロントから設定ファイルを読む口が開かない。パスを Rust 側に閉じる設計と噛み合う
- `Registry` が素の struct になるので、id の発行・重複判定・並び順をユニットテストで書ける
- プラグインを足すと capability の検討も必要になる。使わないなら考えることが減る ([../security.md](../security.md))

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| `tauri-plugin-store` (ADR-0005 のまま) | フロントから読める口が開く。ユニットテストに `AppHandle` が要る |
| SQLite | ADR-0005 のとおり過剰 |
| フロントの localStorage | パスをフロントが持つ設計になる |
| 保存先を自前で決める (`~/.canopy.json` など) | macOS の作法から外れる。`app_config_dir()` に従う |

## 影響

- `src-tauri/src/store/` は Tauri に依存しない。パスは呼び出し側 (コマンド) が渡す
- 設定ファイルが壊れていたときは**握りつぶさずエラーにする**。読めないファイルを黙って初期状態で上書きしない
- 保存する形が変わったら `version` を上げて移行を書く
