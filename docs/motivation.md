# 背景と動機

なぜこのツールを作るのか。  
設計判断の前提になっている事情をここに置く。個別の判断は [adr/](adr/) にある。

## 出発点

Agentic Coding が主になって、エディタを開く頻度が下がった。  
コードを書くのはエージェントに任せて、人がやるのは指示とレビューと Git 操作になった。

それでも Git 操作だけは、**ツリーでブランチを見て切り替える形**が一番手に馴染む。  
ターミナルの `git branch -a` では、今どこにいて何が取り込めるのかが一目で分からない。  
そのために IDE を起動するのは重く、メモリも食う。

## 既存のツールで足りなかったこと

いくつかの Git クライアントを試したが、どれも噛み合わなかった。

**1 リポジトリ 1 ウィンドウが前提になっている。**  
モノレポではないリポジトリを 10 個前後行き来する使い方だと、ウィンドウを切り替えて回ることになる。  
知りたいのは「どのリポジトリに取り込む変更があるか」なのに、それを見るために 10 回操作する。

**機能が多すぎて、日常的に使う部分が埋もれる。**  
実際に毎日触るのは、今の場所を確認して、切り替えて、取り込んで、送るだけ。  
ログと差分はターミナルと GitHub で見ている。

## そこで作るもの

- **複数リポジトリを 1 つのビューに。** 操作なしで全体の状態が分かること
- **ブランチ中心。** コミットや差分ではなく、ブランチの状態と切り替えを主役にする
- **常駐して軽い。** 起動のコストを払わずに、思い立った瞬間に開けること
- **機能を絞る。** 毎日使うものだけ入れる。境界は [adr/0007-v1-scope.md](adr/0007-v1-scope.md)

## 想定している使い方

- macOS で、10 個前後のリポジトリを登録して常駐させておく
- 朝いちばんに全体をフェッチして、取り込むものがあるリポジトリを把握する
- 作業するリポジトリのブランチを切り替えて、取り込む
- 作業が終わったら送る

この使い方に必要なものが v1 のスコープになっている。  
それ以外は入れていない。
