# 作業の進め方

## フェーズの単位

実装は [plans/](plans/) のフェーズごとに進める。  
1 フェーズは「動くものが 1 段増える」単位で切る。  
複数フェーズを同時に進めない。

## フェーズの流れ

```
プランを読む
  ↓
テストを書く → 実装 → 整理   (この 3 つを小さく繰り返す)
  ↓
pnpm check が通ることを確認する
  ↓
自己チェック (下のリスト)
  ↓
サブエージェントのレビュー (必須)
  ↓
指摘の反映と docs の更新
  ↓
プランのチェックボックスを埋めてフェーズ完了
```

## 完了の条件

フェーズを完了と呼べるのは、全部を満たしたときだけ。

- [ ] プランに書いた項目がすべて終わっている。残ったものは次フェーズに移した上で明記した
- [ ] 新しい振る舞いにテストがある
- [ ] `pnpm check` が通っている (実行した出力を確認した)
- [ ] UI を触ったなら、モックと見比べてずれがない
- [ ] 設計判断をしたなら ADR にある
- [ ] サブエージェントのレビューを通し、指摘に対応または見送りの理由を残した
- [ ] 指摘から得た再発防止をルールか仕組みに落とした

## サブエージェントのレビュー

フェーズごとに、観点を分けて並列で投げる。  
1 エージェントに全部見せない。観点を混ぜると浅くなる。

**手順は `phase-review` skill にある。** そちらを使う。

判断の原則だけここに書く。

**推測での指摘を採用しない。**  
「壊れる入力と結果」が示せない指摘は、確認してから直すか見送る。  
レビューは根拠で採否を決める。相手への配慮で曲げない。

## 直したあとの波及確認

**ドキュメントの修正は 1 箇所で終わらない。**  
仕様を直すとプランが古くなり、ADR を置き換えると他のファイルが死んだ ADR を指したままになる。

修正のたびにこれを実行する。

```sh
python3 scripts/check-docs.py
```

検出するのは 6 つ。

- リンク切れ
- ADR 一覧に載っていない ADR、ステータスの表記ゆれ
- 置き換え済み / 破棄した ADR を、ADR 以外のファイルが根拠として指している箇所
- 表の列数が区切り行と合っていない箇所 (見出しだけ足してセルを埋め忘れた表)
- 表に出るファイル (README、`package.json`、`src/`、`src-tauri/` 配下の設定とソース) に入り込んだ特定製品の名前
- 過去に間違えた表現の再発

スクリプトで拾えない波及は手で確認する。**最低限、直した内容が次の 3 箇所に跳ね返っていないかを見る。**

| 直した場所 | 確認する場所 |
| --- | --- |
| `specs/` | `plans/` の該当フェーズ。前提のリンクと、やることの記述 |
| `adr/` | `architecture.md`、`plans/` の前提、置き換えた ADR を指している箇所 |
| `plans/` | `plans/README.md` の一覧 |

**新しく間違えた表現は `scripts/check-docs.py` の `BANNED` に足す。**  
同じ間違いを二度検出できるようにしてから次へ進む。

## 指摘を受けたあと

直すだけで終わらせない。  
[../AGENTS.md](../AGENTS.md) の「指摘を受けたときの扱い」に従って、ルールか仕組みに落とす。

同じ手順を 3 回以上繰り返しているなら skill にする。  
既存の skill は `.claude/skills/` にある。

## 落とし穴

実装で踏みやすいものを [pitfalls.md](pitfalls.md) にまとめている。  
新しく踏んだら追記する。
