# 実装プラン

フェーズごとに 1 ファイル。  
進め方と完了条件は [../workflow.md](../workflow.md) にある。

## 一覧

| フェーズ | 内容 | 状態 |
| --- | --- | --- |
| [0](phase-0-foundation.md) | 土台 (プロジェクト生成、検査コマンド、CI、トークン移植) | 完了 |
| [1](phase-1-read.md) | 読み取り (リポジトリ登録、スナップショット取得、ツリー表示、仮想スクロール) | 完了 |
| [2](phase-2-write.md) | 操作 (チェックアウト / フェッチ / プル / プッシュ / 名前の変更、メニュー、ダイアログ) | 完了 |
| [3](phase-3-around.md) | 周辺 (コンソール、トースト、検索、並び替え) | 完了 |
| [4](phase-4-polish.md) | 仕上げ (見た目の詰め、ウィンドウ状態、ビルドと配置) | 未着手 |

フェーズの粒度は「動くものが 1 段増える」単位。  
このファイルの表と各プランの状態は、フェーズ完了時に必ず更新する。

## プランの書式

各プランに書くもの。

1. **目的** — このフェーズが終わると何ができるようになるか
2. **前提** — 依存する ADR と仕様のリンク
3. **やること** — チェックボックスの一覧。1 項目は 1 コミットに収まる大きさ
4. **テスト** — 何をどの層で確認するか
5. **完了条件** — [../workflow.md](../workflow.md) の共通条件に加えて、このフェーズ固有のもの
6. **やらないこと** — 混ざりやすいが次フェーズに回すもの

必要に応じて足す節。

7. **先に決めること** — 着手前に片付ける判断 (前フェーズのレビューから来たものなど)
8. **決めたこと** — そのフェーズで決めた判断と、入れた依存
9. **確認した内容** — 何をどう確かめたか。実測値はここに書く
10. **レビューで出たこと** — サブエージェントのレビューの指摘と、採否の理由

作業中はチェックボックスを埋めながら進める。  
終わらなかった項目は次フェーズのプランに移して、移した旨を残す。  
**前倒しで終わった項目は、そのフェーズのプランでチェックして「どのフェーズで実装したか」を書く。**
