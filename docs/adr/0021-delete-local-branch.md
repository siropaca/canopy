# ADR-0021: ローカルブランチの削除を v1 に入れる

- ステータス: 採用
- 日付: 2026-09-03
- [ADR-0007](0007-v1-scope.md) の「入れない」から 1 項目を外す

## 背景

[ADR-0007](0007-v1-scope.md) は「ブランチの作成・削除」を v1 に入れないと決めた。  
根拠は「毎日使うのは、今どこにいて pull があるかを見て、切り替えて、取り込んで、出すこと」。

フェーズ 4 のあと 1 週間使って、**掃除だけが手元に残る**ことが分かった。

マージして origin 側で消えたブランチは `gone` として出る。  
それが正しく出るほど溜まっていくのに、アプリの中に消す手段が無い。  
リポジトリを 11 個行き来する使い方だと、掃除のためだけにターミナルへ戻ることになる。

## 決定

- **ローカルブランチの削除を v1 に入れる。** `git branch -d <名前>`
- 既定は `-d`。マージされていなければ git が拒否するので、**その失敗をそのまま見せる**
- ダイアログで「マージされていなくても削除」を選べる。選ぶと `-D` になり、ボタンが赤くなる
- 出すのは**ローカルブランチだけ**。現在のブランチと、別のワークツリーにあるブランチには出さない
- リモートブランチとタグの削除は入れない。ADR-0007 の「入れない」に残す

## 理由

- `gone` を出すと決めた時点で、掃除まで引き受けないと画面が正しいまま使えなくなる
- `-d` は「HEAD か上流にマージ済み」でなければ拒否する。**git の安全策をそのまま使う**のが一番確実で、
  こちらで「マージ済みか」を判定して分岐すると、判定の間に変わった状態で消すことになる
- 強制を独立したチェックボックスにするのは、プッシュのダイアログと同じ形
  ([../specs/ui.md](../specs/ui.md) の「プッシュ」)。破壊的な選択を 1 段増やす
- 現在のブランチと別ワークツリーのブランチは git が必ず拒否する。押せる形にしても失敗しか返らない
- リモートの削除は「他人に見えているものを消す」ので、ローカルの掃除とは危険度が違う

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| v2 のままにする | `gone` を出しているのに片付けられない。画面が正しいほど溜まる |
| `gone` のブランチだけ削除できるようにする | `gone` はマージ済みを意味しない。結局同じ安全策が要るので、実装は減らずに基準だけ分かりにくくなる |
| 「追跡を外す」(`--unset-upstream`) だけ入れる | `gone` の表示は消えるが、ブランチは残る。掃除したいという元の困りごとが残る |
| 最初から `-D` を使う | マージしていないコミットが黙って消える。git がわざわざ止めているものを外すことになる |
| マージ済みかをこちらで判定して出し分ける | 判定と実行の間に状態が変わる。git に聞いて拒否させる方が正しい |
| まとめて掃除する (`gone` を一括削除) | 1 つずつで足りるかを使って確かめてから。消す操作を一括にするのは戻せない |

## 影響

- `OpKind` に削除が増える。締め切りは `LONG_TIMEOUT` 側 (ネットワークを触らない)
- サイドバーの「ブランチの削除」が v2 のグレーではなくなる ([../specs/ui.md](../specs/ui.md) の「サイドバー」)
- ADR-0007 の「入れない」からブランチの**削除**だけが外れる。**作成は入れないまま**
- **折りたたみの鍵は残る。** ブランチの葉は折りたためないので鍵を持たないが、
  中身が空になったディレクトリの鍵は `ui_state.expanded` に残る。
  `Registry::prune` が落とすのは登録が無くなったリポジトリの分だけ。
  同じ名前のブランチを作り直すと、そのディレクトリは開いた状態で出る (折りたたみ状態を保つ挙動として妥当)
