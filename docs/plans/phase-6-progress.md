# フェーズ 6: 実行中の見せ方

## 目的

常用して出た「ボタンが灰色になるだけなので、固まっているように見える」を直す。  
いま何をしているかをステータスバーに出す。

## 前提

- [adr/0023-progress-in-the-status-bar.md](../adr/0023-progress-in-the-status-bar.md) — この判断
- [adr/0009-concurrency-and-refresh.md](../adr/0009-concurrency-and-refresh.md) — 実行中の扱いの元の規定
- [adr/0022-auto-refresh.md](../adr/0022-auto-refresh.md) — 取り直しはボタンを無効にしない
- [../specs/ui.md](../specs/ui.md) の「実行中の扱い」「ステータスバー」

## やること

### 1. 実行中の中身を持つ

- [x] `running` を本数から**操作の列**にする。`beginRun` が種別を受け取る
- [x] 取り直しの最中を持つ `reading` を足す。**`running` とは別**にする
      (混ぜるとボタンが `.git` の変化のたびに無効になる)
- [x] 「実行中か」の判定 (`isRunning`) は変えない

### 2. 文言を組み立てる

- [x] `shared/lib/activity.ts` に純粋関数を 1 本置く
- [x] 書き込み 1 本なら `<名前> を<操作>中`、2 本以上なら `<n> 件を実行中`
- [x] 一括フェッチは `フェッチ <済み> / <全体>`
- [x] 取り直しは 1 件なら `<名前> を更新中`、2 件以上なら `<n> リポジトリを更新中`
- [x] 書き込みと取り直しが重なったら書き込みを優先する

### 3. ステータスバーに出す

- [x] 左端に回るアイコンと文言を出す。何も走っていなければ出さない
- [x] **行の薄さと無効化はそのまま。** 行にスピナーは出さない
- [x] 詳細ペインには何も足さない
- [x] モックにも同じ形を入れる。モックは操作のあと少しだけ実行中を出す

## テスト

| 層 | 内容 |
| --- | --- |
| フロント ユニット | 文言の組み立て。1 本 / 複数 / 一括 / 取り直し / 何も無い |
| フロント ユニット | 書き込みと取り直しが重なったら書き込みを優先する |
| フロント ユニット | 名前が引けないリポジトリでも件数の形で出る |
| フロント ユニット | `running` が操作の列になっても「実行中か」の判定が変わらない |
| コンポーネント | ステータスバー。実行中は文言が出て、終わると集計だけに戻る |
| フロント ユニット | 操作ごとに正しい種別が `beginRun` に渡る (配線) |

## 完了条件

- [x] フェッチ・プル・プッシュ・チェックアウト・削除の最中に、何をしているかがステータスバーに出る
- [x] 「更新」を押すと、押した瞬間から終わるまでステータスバーに出る
- [x] 一括フェッチの残りが数で分かる
- [x] 実行中が無いときのステータスバーは今までと同じ

## やらないこと

- 行ごとのスピナー。一括フェッチで 11 個同時に回る ([adr/0023](../adr/0023-progress-in-the-status-bar.md))
- 個別の操作の進み具合。段数が可変で、Rust から途中経過を送る仕組みが要る
- 詳細ペインへの追加

## 確かめたこと

| 何を | どう |
| --- | --- |
| 書き込みの表示 | 実機で確認した。`canopy をフェッチ中` がフェッチの間ずっと出る |
| 取り直しの表示 | 実機で確認した。`11 リポジトリを更新中` が「更新」を押した瞬間から出る |
| モック | ブラウザで確認した。チェックアウト / チェックアウトとプル / 早送り / 一括フェッチの 4 通りとも実装と同じ文言。一括フェッチは `フェッチ 0 / 11` から `11 / 11` まで進む |
| テストに歯が立っていること | 実装を **8 通り**壊して全部落ちることを確認した。レビューでさらに **9 通り**壊して素通りしたものは、テストを足して落ちるようにした |

## レビューで出たこと

5 観点をサブエージェントに投げた (仕様の一致 / 正しさ / テスト / 設計 / ドキュメント)。  
指摘は 45 件 (仕様 7 / 正しさ 6 / テスト 7 / 設計 6 / ドキュメント 13。重複を含む)。

### 直したもの

| 指摘 | 対応 |
| --- | --- |
| ステータスバーのテストが全部「状態を作ってから描く」形で、購読を切っても 812 件すべて緑 | 描いたあとに `act` で始める形のテストを 4 本足した (取り直し / 書き込み / 一括フェッチの進み / 終わり) |
| 回るアイコンが縛られていない。`animation` を消しても緑 | 突き合わせる項目に `animation` と `transform-origin` を足した。どのアイコンかも形で見る |
| `@media` の中の打ち消しが、外の値を上書きして読まれる | CSS の読み取りが `@` 規則の中身を本文ごと飛ばすようにした。`@keyframes` も拾わない |
| `endRun` がどの操作が終わったかを知らず、列の末尾を抜く | 終わった操作を名指しで渡す形にした。プッシュ中に一括フェッチが重なっても残る側がずれない |
| ステータスバーが一括フェッチの「走っているか」を書き直している | `bulkFetchProgress` を store に足して、判定を 1 本に戻した |
| やり直しが `refreshRepositories` のガードを通らない | 読んでいる間に消えたリポジトリ・書き込みが始まったリポジトリはやり直さない。判定は `shouldRead` の 1 本 |
| 「再帰は 2 段までしか深くならない」が成り立たない | 再帰をやめて繰り返しにした |
| 「読み取りが失敗しても印を外す」テストが失敗経路を通っていない | `loadSnapshot` を差し替えて投げさせる形にした (`getRepoSnapshot` の拒否は `loadSnapshot` が握る) |
| 動詞 7 つのうち 3 つが文字列として縛られていない | チェックアウト / チェックアウトとプル / 名前の変更 を足した |
| 一括フェッチと個別の書き込みが重なったときの決めが無い | 一括フェッチを先にすると決めて、仕様の表を優先順位の順に並べ替えた。テストも足した |
| 初めてアニメーションを入れたのに、止める条件が無い | `prefers-reduced-motion` で回さないようにした |
| ADR-0023 と仕様に同じ表が二重にある | 表と文言は仕様に置いて、ADR は判断と理由だけにした |
| ADR-0009 が「スピナーは出さない」と言ったまま残っている | 該当の節に注記を足した。本文は当時のまま |
| `<操作>` の語彙がどこにも無い | 仕様に 7 つの表を足した |
| モックの鍵が `switch` で、モックが流す `git checkout` に当たらない | モックのコマンドに合わせた。チェックアウトとプル・早送りの取り違えも直した |
| モックに一括フェッチの進み具合が無い | 1 件ずつずらして `フェッチ <済み> / <全体>` を出す形にした |
| `data-model.md` の `running` が「本数」のまま | 操作の列に直した。`reading` も書いた |
| 一括フェッチの見張りの猶予が 60 秒のまま (実装は 630 秒) | 直した。630 秒の根拠も書いた (フェーズ 4 の積み残し) |
| `reading` の説明が実態より広い | 「更新」の 3 つの引き金から走った読み取りだけ、と書いた |
| `architecture.md` の `status-bar` が「集計表示」のまま | 直した |
| `--fg-strong` の用途に実行中が無い | 足した |
| アイコンの表に「更新」だけ足してある | 実行中の行に「更新の丸い矢印とは別の形」と書く形にまとめた |
| プランだけ「フッター」と呼んでいる | 「ステータスバー」に統一した |
| 「実行中の扱い」から取り直しの表示が読み取れない | その節に取り直しのことを書いた |
| `opsActions.test.ts` / `events.test.ts` の `beforeEach` が揃っていない | 揃えた |

### 見送ったもの

| 指摘 | 理由 |
| --- | --- |
| 実行中の文言を左端に入れると、集計が横に動く | 右端に置けば動かないが、いちばん見てほしいものを端に追いやることになる。左端はこちらで決めたレイアウトなので変えない。ADR の影響に書いた |
| 見張りが畳んだあと、次の一括フェッチ中に遅れて届くと `endRun` が余分に走る | フェーズ 6 以前からある。630 秒を超えるのは長い操作 2 本の後ろに並んだ場合だけで再現性が低い。`endRun` を名指しにしたので、別の操作の印を消す部分は消えた |
| `reading` を起動時の読み込みにも広げる | 起動時は見出しの `読み込み中` と合計の `-` で見せている。広げると重複排除の意味が変わって、起動中に届いた `.git` の変化を取りこぼす |
