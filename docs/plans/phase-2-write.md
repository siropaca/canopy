# フェーズ 2: 操作

## 目的

チェックアウト・フェッチ・プル・プッシュ・名前の変更ができる状態にする。  
失敗も正しく失敗として見える。

## やること

### Rust 側

- [x] 直列実行キューを作る。**キーは `git rev-parse --git-common-dir` の実パス。** リポジトリ id ではない (ワークツリーが ref store を共有するため)
- [x] 同一リポジトリ内は書き込み排他・読み取り共有にする
- [x] ネットワーク操作に 30 秒のタイムアウトと kill を入れる。`GIT_SSH_COMMAND` に `ConnectTimeout=5` を渡す
- [x] 同種操作の重複排除。フェッチ連打で 11 本積まれないようにする
- [x] 意図ごとの Tauri コマンドを作る。汎用の実行コマンドは作らない
- [x] **すべての参照引数**を通す共通の検証関数を作る。名前変更だけではない
- [x] 検証は `git check-ref-format --branch <名前>` で行う。加えて `-` 始まり・`@{` を含む・`..` を含む名前を明示的に拒否する
- [x] 参照の切り替えは `git switch` を使う。`--end-of-options` を挟む ([../security.md](../security.md))
- [x] git の非ゼロ終了は `Ok(CommandResult{ok:false})` で返す。`Err` はアプリ側の異常だけ
- [x] 操作の戻り値は `{ result, snapshot }` の 1 つにまとめる。フロントが 2 回 invoke する形にしない
- [x] よくある失敗を判定して文言を付ける ([../specs/git-operations.md](../specs/git-operations.md) の表)。**判定は「操作の種別 × 出力」で行う。** 同じ `(non-fast-forward)` がプルとプッシュで逆の意味になる
- [x] リモートブランチのチェックアウトは、ローカルに同名があるかで分岐する。無ければ `git switch -c --track`、有れば既存に切り替えた旨を返す
- [x] 強制プッシュは `--force-with-lease=<リモート側のブランチ名>:<sha>` で sha を明示する
- [x] 名前変更のあとに `git branch --unset-upstream` を実行する。`-m` は追跡先を旧名のまま残す
- [x] **成否に関係なく**対象リポジトリのスナップショットを取り直して返す。書き込みと同じ直列区間の中で行う
- [x] キューは `tokio::sync::RwLock` (リポジトリごと) + `tokio::sync::Semaphore` (全体) で書く

### フロント側

- [x] コンテキストメニュー。行の種類でメニューを出し分ける。括り行とディレクトリでは出さない
- [x] v2 の項目をグレーで置く。押しても何も起きない
- [x] ダイアログの共通の枠を作る
- [x] ブランチ名の変更ダイアログ
- [x] プッシュダイアログ。コミット一覧、強制プッシュのチェック、ボタンの色と文言の変化
- [x] 詳細ペインのボタンを動かす
- [x] サイドバーのフェッチとプルを動かす。選択に応じた有効・無効
- [x] ダブルクリックでチェックアウト
- [x] 実行中はそのリポジトリの操作系 UI を無効にする。行を薄くする。スピナーは出さない
- [x] detached HEAD から戻る「直前のブランチに戻る」を入れる
- [x] `⧉` が付いたブランチのチェックアウトを無効にする (必ず `already used by worktree at` で失敗するため)
- [x] `⧉` が付いたブランチのプルは、そのワークツリーで実行する
- [x] `gone` が付いたブランチのプルを無効にする
- [x] 強制プッシュのチェックボックスは ahead が 0 のとき無効にする。behind だけのブランチに撃つとリモートを巻き戻す


## フェーズ 1 のレビューから持ち越した設計課題

書き込みのコマンドを足すときに、先にこれを片付ける。

- [x] **並行制御の合成を 1 箇所に出す。** いまは `get_repo_snapshot` が
      「locate → 読み取りの permit → revision の採番 → build_snapshot」の順序を直接持っている。
      書き込みが 6〜7 本乗ると「locate → 書き込みロック → 参照名の検証 → git → **同じロックの中で**
      取り直し → `{result, snapshot}`」が各コマンドに複製される。
      `&AppState` を受ける関数に落とせば、順序を守っていることをユニットテストで固定できる
      (`AppState::load(path)` は Tauri 無しで作れる)
- [x] **`commands/repo.rs` を分ける。** いまは設定の CRUD・追加フロー・スナップショット読みの 3 役。
      操作系を足す前に `commands/settings.rs` / `commands/snapshot.rs` / `commands/ops.rs` へ分けると、
      `generate_handler!` のパス書き換えが 1 回で済む
- [x] **行の述語を `shared/lib/selection.ts` に集める。** `⧉` 付きはチェックアウト無効、
      `gone` はプル無効、ahead 0 なら強制プッシュ無効、実行中はそのリポジトリの操作系すべて無効。
      サイドバー・コンテキストメニュー・詳細ペインの 3 features が同じ入力から判断するので、
      features には置かない (フェーズ 1 で `canPullSelection` / `isFoldable` を置いた場所)
- [x] **「画面に見えている選択」を `store/useSelectedRow.ts` に出す。** いまは `app/App.tsx` が
      `rows.find` で解いて props で配っている。コンテキストメニューとダイアログが同じものを要る
- [x] **`RepoState` に「実行中」が増えたときの参照経路を 1 本にする。** 正はストア側
      (`src/ipc/types.ts` の `RepoRow` に注記済み)

## 決めたこと

依存パッケージは増やしていない。  
`tokio` の feature に `time` を足しただけ (ネットワーク操作の締め切りに `tokio::time::timeout` を使う)。

新しく書いた ADR。

| # | 判断 |
| --- | --- |
| [ADR-0017](../adr/0017-typed-git-arguments.md) | git に渡す引数を型で縛る (`Arg` / `RefName` / `ObjectName` / `Composed`) |
| [ADR-0018](../adr/0018-command-result-steps.md) | 操作の結果は「段」の列 + 終わり方の判別子で返す |

**この 2 つはフェーズ 2 のレビューで書き直した。**  
最初は `RefName` / `ObjectName` を用意するだけ、結果は段の数で終わり方を見分ける形だったが、
どちらもレビューで穴を指摘されて作り直した。経緯は各 ADR の「検討した他の案」にある。

決めたこと。

- **順序を持つのは `src-tauri/src/ops.rs` の 1 箇所。** locate → 重複排除 → ネットワークの枠 →
  書き込みロック → 実行 → **同じロックの中で**取り直し。`&AppState` を受ける関数なので Tauri 無しでテストできる
- **ネットワークの枠はロックの前に取る。** ロックを持って枠を待つと、一括フェッチ中に同じ
  リポジトリのチェックアウトが待たされる (完了条件の 1 つ)。順序を壊すと落ちるテストを置いた
- **リポジトリごとのロックは `RwLock`。** ADR-0009 の「並行モデル」は `Mutex` と書いているが、
  同じ ADR の「排他の粒度」は「書き込み排他・読み取り共有 (RwLock 相当)」と決めている。
  後者に合わせた。読み取り (`get_repo_snapshot`) も共有ロックを通す
- **一括フェッチの枠はネットワークの枠より 1 つ小さい** (3 / 4)。対話操作の分を残す
- **同種操作の重複排除は「省略して、いまの状態を返す」。** `CommandResult.kind` が
  `skipped` になる。積まないので、フェッチ連打で 11 本にならない。
  **段の数では見分けない** (コピーやアプリ側の異常も 0 個になる)
- **早送りとプッシュのリモートは追跡先から取る。** 仕様は `origin` 決め打ちだったが、
  `upstream/main` を追跡しているブランチで別のブランチの中身を上書きしてしまう。
  [../specs/git-operations.md](../specs/git-operations.md) の表を直した
- **`⧉` が付いたブランチのプルは Rust 側が切り替える。** フロントはパスを持たない。
  `worktree list` を見て、そのワークツリーで `git pull --rebase` を実行する
- **打ち切るのはフェッチとプッシュだけ。** `git pull --rebase` を途中で殺すと
  `.git/rebase-merge` が残り、v1 に `rebase --abort` の入口が無いので復帰できない。
  打ち切らない操作にも 600 秒の天井を置く (分岐にすると消しても気づけない)
- **プッシュは push 先を `<ローカル>:<上流>` で明示する。** 省くと git は同名の ref を
  更新するので、上流の名前が違うブランチでリースが更新しない ref に付く
- **取り直しに失敗しても実行した git の出力は返す。** `OpOutcome.snapshot` を
  optional にした。`Err` にすると stdout / stderr が消える (ADR-0009 が避けた状態)
- **`--unset-upstream` は追跡先があるときだけ実行する。** 無いブランチに撃つと失敗する
- **出力の認証情報は Rust 側でマスクしてからフロントに返す。**
  フェーズ 3 の項目だったが、`CommandStep` を作る場所が 1 箇所なので前倒しした
- **「最後の結果」は詳細ペインの一番下に出す。フェーズ 2 限りの表示。**
  コンソールとトーストはフェーズ 3 なので、それまで結果がどこにも出ないのを避ける。
  **モックには無い**ので、[../specs/ui.md](../specs/ui.md) に注記した
- **補助操作 (コピー / Finder / ターミナル) はこのフェーズに入れた。** メニューの項目が
  v1 なのに押しても何も起きない状態を残さないため ([../adr/0015-auxiliary-operations.md](../adr/0015-auxiliary-operations.md))。
  ターミナルアプリ名は設定ファイルに持つ (既定 `Terminal`、v1 に設定画面は無い)
- **行の述語は `shared/lib/selection.ts` に集める。** `running` を `RowNode` に写して、
  行だけで判定できる形にした (`dirtyCount` と同じ扱い)。
  **「実行中」の正は本数 1 本**で、`orderedRepos` が写す
- **実行中は本数で数える。** 一括フェッチとユーザーの操作が重なったとき、真偽値だと
  先に終わった方が実行中の表示を消す
- **一括フェッチは購読が生きていないときだけ 1 件ずつ投げる形に落ちる。**
  イベントが来ない状態で実行中の印を付けると、そのリポジトリの操作系が永久に無効になる

| --- | --- |
| Rust ユニット | コマンド組み立て。参照名の検証。`-` 始まりや空白入りの名前を弾くこと |

### 実機で見つけた不具合

どれもテストでは見えず、画面を触って見つけた。

- **無効なプライマリボタンが押せるように見える。** 濃い青の上に `--disabled` の文字が乗って読めない。
  背景と枠も戻すようにして、モックの CSS も直した
- **ダイアログの無効なプライマリボタンに無効の見た目が無い。** 同じ原因
- **StrictMode で購読が 2 本張られ、1 本外れた時点で「購読していない」と判定していた。**
  一括フェッチが 1 件ずつ投げる形に落ちていた。本数で数える形に直した
- **ブランチのメニューでコピーの項目に値が出ていた。** 値を出すのはリポジトリ見出しの
  サブメニューだけ (モックと違っていた)

### 残した振る舞い

- **コンフリクトで止まった rebase は `detached: <ハッシュ>` として出る。**
  git は rebase 中に HEAD を detached にするので、`git branch --show-current` が空を返す。
  「元のブランチのまま」ではないので完了条件は満たすが、`rebase 中` という表示は持っていない。
  フェーズ 4 の見た目の詰めで判断する
- **アプリ終了時に実行中の子プロセスを kill する** (ADR-0009) は入れていない。
  締め切りでの kill (`kill_on_drop`) は入っている。git の操作は最長 30 秒で終わるので、
  常駐の実装が入るフェーズ 4 に回した

## レビューで出たこと

5 観点をサブエージェントに投げた (仕様の一致 / 正しさ / テスト / 設計 / ドキュメント)。  
指摘は 59 件 (仕様 6 / 正しさ 8 / テスト 17 / 設計 13 / ドキュメント 15)。  
採用 57 件、見送り 2 件。  
反映の途中で実機を触り直して、さらに 1 件 (リースの sha が無いのに強制プッシュを選べる) を見つけた。

### 表に出る不具合として直したもの

- **`gone` ブランチのプッシュがダイアログごと消える。** 追跡設定は残るので `%(upstream:...)` は
  名前を返すが ref が無いので `git log <上流>..<名前>` が exit 128。`gone` はプルが無効なので
  プッシュが唯一の復旧手段だった
- **`git pull --rebase` を 30 秒で殺していた。** rebase の途中で死ぬと `.git/rebase-merge` が残り、
  v1 からは復帰できない。打ち切るのはフェッチとプッシュだけにした
- **`--force-with-lease` が push しない ref に付いていた。** 上流の名前が違うブランチ
  (`dev` が `origin/main` を追跡) でリースが効かず、永久に `stale info` で拒否される
- **一括フェッチで「実行中」が永久に残る経路。** 印を invoke の後に付けていたので、
  イベントが先に届くと `endRun` → `beginRun` の順になって 1 のまま残る
- **メニューとダイアログが開いた瞬間の行を掴んでいた。** 一括フェッチが始まっても
  「実行中」が古いままで、無効にすべき項目が押せた
- **ローカルの権限エラーを「認証に失敗しました」と言っていた。** `.git/index.lock` が
  作れないだけなのに SSH 鍵を疑うことになる
- **取り直しの失敗が実行した git の出力を捨てていた。** ADR-0009 が避けた状態が復活していた
- **実行中に「リストから削除」が押せた。** 消すと走っている操作の結果を捨てる先が無くなる
- **読み込み中に強制プッシュを確定できた。** ボタンが「強制プッシュ」を出しながら通常プッシュが走る
- **リースの sha が無いのに強制プッシュを選べた。** `gone` のブランチで
  ボタンが「強制プッシュ」を出しながら通常プッシュが走る
- 無効なプライマリボタンが読めない (詳細ペインとダイアログの 2 箇所)、
  StrictMode で購読の判定が壊れる、メニューのコピー項目に余計な値
  (この 4 件は実機で自分が見つけた)

### 仕組みに落としたもの

- **ADR-0017 の「型で守る」を本当に効かせた。** 実行関数が `&[&str]` を受けていたので、
  v2 で操作を足すときに未検証の名前を渡せた。`Arg` / `Composed` に変えて、
  レビュアーが挙げた `one(dir, kind, &["branch", "-D", name])` が
  **コンパイルエラーになることを実測で確認**
- **`CommandResult` に終わり方の判別子を足した。** 段の数で見分ける形だと、
  省略とアプリ側の異常が同居する
- **eslint の穴 3 つを塞いだ。** `ipc` → `store`、features 同士の相対 import、
  `shared` からの `@tauri-apps` 直 import。**わざと違反するファイルを作って 3 件とも error になることを確認**
- **締め切りの「付けるか付けないか」の分岐を撤去した。** 分岐があると、消しても
  振る舞いで見分けられない
- **`OpKind` を `git` から出した。** `queue` が `git` に依存しない形にした
- **誤表現 2 つを `check-docs.py` の `BANNED` に足した。** 足した直後に、
  自分が見落としていた 2 箇所を検出した

### テストの穴を埋めた

テストレビューは「実装を 18 通り壊して落ちるか」で検証し、14 通りが素通りしていた。  
埋めたあと Rust 3 通り + フロント 10 通りで再検証して、全部落ちることを確認した。

特に効いたもの。

- `check-ref-format` の実行を `if false` にしても 211 本すべて緑だった →
  空白・`~`・`^`・`:`・`.lock` など **git だけが弾く 10 種**のテストを足した
- `git fetch` から `--prune` を落としても緑 → `gone` の検出と消えた追跡 ref の両方を見る形にした
- `app.emit` を止めても緑 → mock アプリでイベントを購読する統合テストを足した
- `read_snapshot` から共有ロックと枠を消しても緑 → 外からロックを握って待つことを確認する形にした
- `useRowActions` にテストが 0 本 → メニュー 11 項目の割り振り、ダブルクリック、
  名前変更の引数順、プッシュの sha を固定した

### 見送ったもの

- **打ち切ったときに stdout / stderr が空になる。** 部分出力を拾うには、全 git 実行が通る
  経路に並行読み取りを入れることになる。git では「途中まで出して固まる」子プロセスを
  作れないので検証できず、未検証の並行処理を置く方がリスクが高いと判断した。
  コマンド行と文言はコンソールに残る。仕様に明記した
- **打ち切りで孫プロセス (`ssh`) が残る。** `kill_on_drop` は直の子だけを殺す。
  プロセスグループの扱いになるので、アプリ終了時の kill と一緒にフェーズ 4 へ移した
