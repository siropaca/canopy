# ADR-0002: git はライブラリではなく CLI を呼ぶ

- ステータス: 採用
- 日付: 2026-08-21

## 背景

git の操作を Rust 側から実行する必要がある。  
`git2` (libgit2) を使う方法と、`git` コマンドを子プロセスで実行する方法がある。

## 決定

`git` コマンドを子プロセスで実行する。

## 理由

- **認証がそのまま動く。** SSH agent、credential helper、1Password、`gh` の設定を何も書かずに使える。libgit2 では自前で面倒を見ることになる
- **手元の git と挙動が一致する。** `.gitconfig` の設定 (rebase の既定、pull の戦略、hooks) が反映される
- **出力をそのままコンソールに出せる。** このツールはコンソールで git の生の出力を見せる仕様なので、CLI の出力が最初から手に入るのは大きい
- 実装が薄い。パースだけ書けばよい

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| `git2` (libgit2) | 認証を自前で実装することになる。hooks と設定の再現も自分で持つ必要がある |
| `gitoxide` | 同上に加えて、書き込み系の成熟度をこの用途で確かめる手間が大きい |

## 影響

- 出力のパースが必要。人間向けの出力に依存せず `--porcelain` と `--format` を使う ([../specs/git-operations.md](../specs/git-operations.md))
- git がインストールされている前提になる (macOS では実質問題にならない)
- **例外が 1 つある。** プルは `pull.rebase` の設定を見ずに `--rebase` を固定する ([../specs/git-operations.md](../specs/git-operations.md))。「設定がそのまま反映される」という利点をここだけ意図的に捨てている
- 子プロセスの起動コストがかかる。読み取りは並列に投げて体感を稼ぐ
- コマンド組み立てが攻撃面になる。対策は [../security.md](../security.md)
