# ADR-0026: ツリーの空いた所を押すと選択を外す

- ステータス: 採用
- 日付: 2026-09-25

## 背景

サイドバーのフェッチは「選択があればそのリポジトリ、無ければ全リポジトリ」と決めていた ([../specs/ui.md](../specs/ui.md) の「サイドバー」)。

ところが**ユーザーが自分で選択を外す手段が無い。**  
「選択なし」になるのは、起動した直後、選んだ行を畳んで隠したとき、選んでいたものをブランチの削除やリストからの削除で消したときだけ。  
一度でも行を押すと、サイドバーのフェッチは 1 件だけのフェッチになり、全リポジトリをフェッチするにはメニューの `すべてフェッチ` を探すことになる。

押す前にどちらになるかも分からない。  
ツールチップは `フェッチ` としか出ていない。

## 決定

**ツリーの行が無い所を押すと選択を外せるようにして、サイドバーのフェッチの名前に対象を出す。**

- 行が無い所は、最後の行より下の空いた部分。検索欄とスクロールバーは含めない
- **最後の行の下に 2 行ぶんの余白を置く。** ツリーが画面より長くても、一番下までスクロールすれば必ず押せる所がある
- 外すのは左ボタンで押したときだけ。右クリックと Ctrl+クリック (macOS では右クリックと同じ) では何もしない
- 名前 (ツールチップと読み上げ) は `フェッチ (すべて)` / `フェッチ (<リポジトリ名>)`。対象は「画面に見えている選択」で決める
- フェッチの振る舞いそのもの (選択で対象を変える) は変えない

## 理由

- **いまの振る舞いを残したまま、選択なしに戻る道を作る。** 1 件だけのフェッチをサイドバーから押す使い方もそのまま残る
- **ファイルのツリーでよくある動き。** Finder やエディタのサイドバーも空いた所を押すと選択が外れる
- **余白を置く。** 仮想リストの器は行の高さぴったりなので、置かないとツリーが画面より長いときに押せる所が 0px になる
- **押す前に対象が分かる。** 選択の有無で対象が変わるボタンなのに、何も出ていないのが迷う原因だった。  
  名前と動作は同じ判断 (`fetchTargetOf`) を見る。別々に書くと、片方だけ直したときに名前と実際の対象が食い違う

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| サイドバーのフェッチを常に全リポジトリにする | サイドバーから 1 件だけのフェッチができなくなる。メニューと詳細ペインには残るが、今の使い方を変える |
| Esc で選択を外す | キーボード操作は持たない ([ADR-0008](0008-no-keyboard-shortcuts.md)) |
| 選んでいる行をもう一度押すと外す | ダブルクリックの 1 回目で選択が外れる。押すたびに状態が反転するのは読みにくい |
| 選択を外すボタンをサイドバーに置く | ボタンが 1 つ増えるわりに、使うのはフェッチの前だけ |
| ツールチップだけ変える | 何が起きるかは分かるが、全件にする手段は増えない |
| 余白を置かず、空いた所があるときだけ外せる | ツリーを展開していると外せない。11 リポジトリを展開した常用の状態がちょうどこれ |

## 影響

- ツリーの一番下に 2 行ぶんの余白が常にある
- ツリーが画面より長いと、空いた所は一番下までスクロールしないと出てこない。  
  そのときは選んだ行を畳むか、メニューの `すべてフェッチ` を使う
- 選択を外すと詳細ペインは「ブランチを選択」に戻り、選択依存のボタンは無効になる。  
  畳んで隠したときと違い、選択そのものが消えるので開き直しても戻らない
- ツールチップの名前はボタンの読み上げの名前も兼ねている。選択で名前が変わる
