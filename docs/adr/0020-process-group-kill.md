# ADR-0020: 子プロセスはグループごと畳む

- ステータス: 採用
- 日付: 2026-08-27

## 背景

[ADR-0009](0009-concurrency-and-refresh.md) は「フェッチとプッシュに 30 秒の締め切りを付けて、超えたら子プロセスを kill する」「アプリ終了時に実行中の子プロセスを kill する」と決めた。  
フェーズ 2 で締め切り側だけを `kill_on_drop(true)` で実装した。

これが 2 つとも足りていない。

- **`kill_on_drop` は直の子だけを殺す。** リモートが SSH のとき `git fetch` は `ssh` を起こすので、打ち切ったあとも接続待ちの `ssh` が残る (実測)
- **`kill_on_drop` は future を落としたときにしか走らない。** アプリが終了する経路では future が落ちないので、終了時の kill が実現できていない

打ち切りの実装にもう 1 つ穴があった。  
締め切りを `wait_with_output()` に掛けていたので、**打ち切ると stdout / stderr が丸ごと消える。**  
コンソールにコマンド行だけが残り、どこまで進んで止まったのかが追えない。

## 決定

- 子プロセスを**自分のプロセスグループの先頭**にする (`process_group(0)`)
- 締め切りを過ぎたら、そのグループを `killpg` でまとめて畳む。孫の `ssh` も一緒に消える
- 走っている子のグループ id を**プロセス内の 1 か所**に控える (`git/children.rs`)。アプリの終了時にそこを全部畳む
- 締め切りは `wait_with_output()` ではなく、**自分でパイプを読みながら**掛ける。打ち切っても読めた分は残す
- `killpg` のために `libc` を依存に足す

## 理由

- グループを作らないと、殺す相手を「直の子」より広げられない。pid を辿る方法はレースがあり、`ssh` が更に子を持つと追い切れない
- `killpg` の相手は「まだ `wait` していない子」なので、pid が別のプロセスに割り当て直されることがない。控えを持つのはこの範囲に限る
- パイプを読まずに `wait()` だけを待つと、出力が 64KB を超えた時点で子が書き込みでブロックして、締め切りまで何も進まなくなる。**両方のパイプを同時に読む**
- `read_to_end` は tokio が「キャンセル安全ではない。読んだ分が失われ得る」と宣言している側の API。`read` は「キャンセル安全」と宣言されているので、そちらを回して自分で貯める
- `libc` は `tokio` が推移的に持っているので、`Cargo.lock` に増えるクレートが無い

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| `kill_on_drop` のままにする | 孫が残る。アプリ終了の経路では走らない。ADR-0009 の決定を満たせない |
| 子の pid から子孫を辿って 1 つずつ kill する | `ps` を読む間に増減する。`ssh` が更に子を持つと辿り切れない |
| `libc` を入れず `/bin/kill -- -<pgid>` を起こす | プロセスを殺すためにプロセスを起こす。失敗しても分からない |
| 終了時に打ち切って良い種別だけ撃つ | 親が死ぬとパイプが閉じるので、残した子も次の出力で `SIGPIPE` で死ぬ。守れない (「影響」に書いた) |
| 打ち切ったら出力を捨てたままにする | 締め切りで落ちた理由がコンソールに何も残らない。**一番知りたい場面で消える** |
| 打ち切りのあと `wait()` してから出力を読む | パイプを読まずに待つと、出力が多い子は書き込みでブロックして返らない |

## 影響

- git を起こす入口は `git::children::spawn_registered` の 1 本になる。直に `spawn()` すると終了時の一括 kill が拾えない
- 終了時の kill は `RunEvent::Exit` から呼ぶ。ここを外すと ADR-0009 の決定が静かに満たされなくなる
- グループを作るのは Unix の API なので、macOS 以外へ広げるときは書き直しになる ([ADR-0014](0014-macos-only.md) の範囲では問題にならない)
- 打ち切った実行は**終了コードを持たない** (`None`)。締め切りと同時に子が正常終了しても「成功」にはしない
- **終了時は種別を問わず畳む。** `git pull --rebase` の途中で終了すると `.git/rebase-merge` が残る
  ([specs/git-operations.md](../specs/git-operations.md) は「打ち切って良いのはフェッチとプッシュだけ」と書いているが、
  終了の経路はそれを守れない)。残した子も、親が死んでパイプが閉じた時点で `SIGPIPE` で死ぬので、
  待たずに畳む方が状態が読める。**残った rebase はフェーズ 4 で「リベース中」として画面に出る**ので、
  ターミナルで `git rebase --abort` すれば戻せる。終了前に確認を出すかは v2 の判断
