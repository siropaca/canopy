# ADR-0010: 仮想スクロールはコンソールだけにする

- ステータス: 破棄
- 日付: 2026-08-21

> **破棄した理由。**  
> 「仮想スクロールにする」という要望の本来の意図は「**web 標準のスクロールバーを出したくない**」ことだった。  
> この ADR は意図を「性能」と読み違えて、実測で不要と結論づけていた。  
> 全リストを仮想化したまま、スクロールバーを自前で描く方針を [ADR-0012](0012-scrollbar-and-virtualization.md) に書いた。  
> なお、ここで挙げたドラッグ並び替えとの衝突は実在する問題なので、ADR-0012 で解決手段を決めている。

## 背景

ADR-0004 は「リモート込みで 400 行規模」を理由にツリーを仮想化すると決めた。  
しかし 400 行が実際に遅いかを測っていなかった。

実データ (11 リポジトリ) で測った結果。

| 状態 | 行数 |
| --- | --- |
| 既定 (リモートとタグは閉) | 約 70 行 |
| 全展開・グループ化オフ | 約 450 行 |

1 行あたりの DOM 要素は 6 個程度なので、全展開でも 3,000 ノード弱。  
WKWebView で問題になる規模ではない。

一方で、ツリーを仮想化すると次が成立しなくなる。

- **リポジトリのドラッグ並び替え** — 画面外の行は DOM から消えるので、離れたリポジトリにドロップできない。挿入線の位置と実際の着地点もずれる (展開中のリポジトリの見出しの「下」は、配下 50 行の後ろ)
- **検索時の全展開** — 行数が激しく変わるのでスクロール位置の復元を自前で持つ必要がある
- **選択行へのスクロール** — 同様

## 決定

- **ツリーは仮想化しない。** 全件描画する
- **コンソールだけ仮想化する。** 出力は使うほど増え続けるため
- 行の**平坦化は仮想化と無関係に行う。** `flatten()` で `RowNode[]` を作る形は維持する
- スクロールバーを目立たせないのは CSS で行う。仮想化とは別の話

## 理由

- 実測して不要と判断した。400 行のために失うもの (並び替え・スクロール復元) が大きすぎる
- 平坦化は折りたたみとグループ化の解決に必要で、仮想化の有無に関係なく有用
- ユーザーの要望は「スクロールバーを目立たせたくない」だった。それは `::-webkit-scrollbar` の指定で達成できる。仮想化は手段として噛み合っていない

## 検討した他の案

| 案 | 採らなかった理由 |
| --- | --- |
| ツリーも仮想化する (ADR-0004) | 実測で不要。ドラッグ並び替えが成立しなくなる |
| 仮想化を残して並び替えを別 UI にする | 並び替えのためだけに専用ダイアログを作ることになる |
| `content-visibility: auto` を使う | 全件描画で足りているので、必要になったら試す |

## 影響

- `@tanstack/react-virtual` の適用範囲はコンソールだけ
- ツリーのドラッグ並び替えは素直に実装できる。「ドラッグ中に全リポジトリを畳む」回避策は不要になる
- 行数が増えて遅くなったら、そのとき改めて測って判断する。目安は 1,000 行
