# フェーズ 3: 周辺

## 目的

日常的に使える状態にする。  
実行結果が追えて、検索で目的のブランチに辿り着けて、並びと状態が次回も保たれる。

## やること

- [x] コンソール。リポジトリごとのタブ、読み取り専用、行の色分け、タイムスタンプと作業ディレクトリ。**`CommandResult.steps` の 1 段が 1 ブロック** ([../adr/0018-command-result-steps.md](../adr/0018-command-result-steps.md))
- [x] 詳細ペインの「最後の結果」を消す。フェーズ 2 限りの表示だった ([phase-2-write.md](phase-2-write.md) の「決めたこと」)
- [x] コンソールも仮想スクロールにする。出力は増え続ける
- [x] タブの開閉、失敗を示す赤いドット、タブが無いときの表示
- [x] トースト。成功は 4 秒、失敗は 9 秒。最大 6 件
- [x] 一括操作は 1 件に集約する (`11 リポジトリをフェッチしました (失敗 2)`)。リポジトリごとに出すと上限を超えて失敗が押し出される
- [x] 一括操作の実行中はそのボタンを無効にする
- [x] 失敗トーストの `詳細を見る` からそのリポジトリのコンソールを開く
- [x] 検索。ローカル・リモート・タグを横断。ヒットしたディレクトリを自動で開く。**UI はここで作る** (`flatten` 側はフェーズ 1 で実装済み)
- [x] `flatten` をリポジトリ単位に切り出してメモ化する。いまは全リポジトリ一括の 1 関数で、検索時に `countHits` と `group` が同じ判定を 2 周する (シグネチャは変えない)
- [x] 検索でヒットしないリポジトリも見出しを薄く残す
- [x] リポジトリのドラッグ並び替え。**ドロップ位置は仮想化リストのインデックスから決める** (DOM のヒットテストに頼らない)
- [x] 挿入線はリポジトリのブロック境界に描く。見出しの下に出すと配下の行の後ろに着地して線とずれる
- [x] 端でのオートスクロール。並び替えても折りたたみ状態を保つ
- [x] グループ化とローカルのみ表示のトグル (`flatten` の引数はフェーズ 1 で用意済み)
- [x] ツリーペインのリサイズ (フェーズ 1 で実装。`src/shared/ui/Splitter.tsx`)
- [x] 永続化。項目は [../specs/data-model.md](../specs/data-model.md) の `UiState`。まとめて保存する (デバウンス)。フェーズ 1 で実装 (`src/store/persist.ts`)
- [x] 保存するのは**開いているキー** (`expanded`)。折りたたんでいるキーではない。既定が閉なので、逆にすると数百キーになる。フェーズ 1 で実装
- [x] 読み込み時に存在しないキーを捨てる。`fetch --prune` で消えた ref のキーが溜まらないようにする。フェーズ 1 で実装 (Rust 側の `Registry::prune`)
- [x] 出力に含まれるトークンをマスクする ([../security.md](../security.md))。フェーズ 2 で実装 (`git::mask_credentials`)。`CommandStep` を作る場所が 1 箇所なので前倒しした

## 決めたこと

依存パッケージは増やしていない。  
ADR-0012 が挙げていた `@dnd-kit/*` は入れずに、並び替えを自前で書いた。

新しく書いた ADR。

| # | 判断 |
| --- | --- |
| [ADR-0019](../adr/0019-reorder-without-dnd-kit.md) | ドラッグ並び替えは dnd-kit を使わず、仮想リストのインデックスで自前で書く |

決めたこと。

- **結果をコンソールとトーストへ流す場所を 1 本にした** (`store/results.ts`)。
  置き場所の理由は [../architecture.md](../architecture.md) の「データフロー」
- **出し分けは `kind` で決める。** `steps.length === 0` で「git を実行しなかった」を判定しない
  ([../adr/0018-command-result-steps.md](../adr/0018-command-result-steps.md))
- **コンソールに出すのは `ran` だけ。** 省略 (`skipped`) とコピー・Finder・ターミナル (`direct`) は
  段を持たないのでタブを作らない。**その代わり失敗トーストの `詳細を見る` も出さない。**
  出すと空のタブへ飛ばすことになる
- **成功しても伝えるべき文言があれば、コマンドの代わりにそれを出す。** リモートブランチの
  チェックアウトが既存のローカルへの切り替えになった場合がこれ
- **成功した段の stderr は赤くしない。** git は進捗を stderr に書くので、一律で赤にすると
  フェッチが毎回失敗したように見える
- **赤いドットを立てるかは呼び出し側 (`store/results.ts`) が決める。** 見えているタブに印を
  付けても、消すための操作 (タブを開く) が無い。パネルを開いた時点でも消す
- **一括フェッチの集計は投げる前に始める。** イベントは invoke の解決より先に届き得る。
  実際に走った一覧が返ってきたら `retarget` で差を埋める (外れた id を待つとボタンが戻らない)
- **コンソールの行は高さを実測する。** 出力は折り返すので固定高だと行が重なる。
  ツリーは行高が一定なので実測しない (`VirtualRows` の `measure`)
- **`flatten` のメモ化の鍵は「そのリポジトリの開いている鍵」だけを見る。** `expanded` の集合
  そのものを鍵にすると、隣のリポジトリを開いただけで全件が作り直しになる
- **検索は 120ms 遅らせてからストアへ渡す。** 打った文字はすぐ画面に出す
- **ドロップ位置はブロックの中央で前後を分ける。** 展開しているリポジトリは高いので、
  見出しの行だけで判定すると配下の行の上に落としたときに戻れない
- **`UiState` に `serde(default)` を付けた。** 保存する項目が増えるたびに、前の版で書いた
  設定ファイルが「壊れている」と判定されると登録したリポジトリごと読めなくなる

### 実機で見つけた不具合

どちらもテストでは見えず、画面を触って見つけた。

- **フェッチを 1 回押すと画面が真っ白になる。** `orderedRepos` が「実行中」を写すたびに
  新しい行を作っていたので、`useShallow` の比較が毎回外れて再描画が止まらなくなっていた
  (`Maximum update depth exceeded`)。**フェーズ 2 から入っていた不具合。**
  控えを持って同じ入力なら同じオブジェクトを返す形に直し、ストアとステータスバーの両方にテストを置いた
- **コンソールを開いても、見えているタブの赤いドットが残る。** 閉じている間に届いた失敗の印を
  消す操作が無かった。パネルを開いた時点で、見えているタブの印を消すようにした

### 残した振る舞い

- **コンソールの出力に上限を置いていない。** タブを閉じるまで積み上がる。
  1 セッションで問題になる量ではないと判断した。上限を入れるなら、
  黙って捨てずに「古い出力を省略した」と出す
- **一括フェッチの結果が 1 件でも届かないと、ボタンが無効のままになる。**
  イベントは全リポジトリぶん必ず飛ぶ (失敗も `RepoUpdate` で返る) 前提。
  取りこぼしの検出はフェーズ 4 の常駐の話と一緒に見る

## レビューで出たこと

5 観点をサブエージェントに投げた (仕様の一致 / 正しさ / テスト / 設計 / ドキュメント)。  
指摘は 60 件 (仕様 7 / 正しさ 8 / テスト 17 / 設計 10 / ドキュメント 18)。  
採用 57 件、見送り 3 件。

**テスト観点がいちばん効いた。** 実装者が確認した 31 通りとは別の壊し方を 20 通り試して、
**17 通りが素通りした。** 穴を埋めたあと 28 通りで再検証して、全部落ちることを確認した。

### 表に出る不具合として直したもの

- **集約が済んだ一括フェッチを `retarget` が復活させて、フェッチのボタンが再起動まで無効になる。**
  結果が全部届いてから `fetch_all` の戻り値が解決する順序で起きる (「集計は投げる前に始める」の裏返し)。
  走っていないときの `retarget` は無視する形に直した
- **出力の無いタブを開けてしまい、コンソールが空のまま戻せなくなる。** タブを閉じたあとに
  そのリポジトリのトーストの `詳細を見る` を押すと起きる。`activeTab` が非 null になるので、
  他のリポジトリの出力が届いても切り替わらない
- **サイドバーの「リストから削除」が実行中でも押せる見た目のまま。** 押しても何も起きない
  (`App.tsx` 側で弾いていた)。詳細ペインとも食い違っていた
- **読み込み中 / エラーのリポジトリの詳細ペインだけ、実行中でも削除できた。**
  一括フェッチ中に消すと、あとから届いた結果でコンソールのタブが id 名で復活する
- **スナップショットが届くたびにツリーが選択行へ引き戻される。** 追従の判定が配列の同一性
  だけだったので、並びが変わらない更新でも走っていた。一括フェッチで 11 回連続で起きる
- **コンソールのコマンド行が、実際に git を走らせた場所と違うことがある。**
  別のワークツリーにあるブランチのプルはそのワークツリーで走る。`CommandStep` に `dir` を足した
- **読み込み中のリポジトリが、検索中は「ヒット無し」として薄くなる。** 起動直後に検索すると
  まだ読めていない分が全部薄くなる
- **設定の保存に失敗しても画面に何も出ない。** `store/notify.ts` を足してトーストに出す
  (コメントが「フェーズ 3 でトーストにする」のまま残っていた)
- **メモ化の鍵が、`,` と `|` を含むブランチ名で衝突する。** 別々の折りたたみ状態が同じ鍵になり、
  開いたディレクトリの中身が出てこない
- **ドラッグの後始末が `pointerup` 頼みで、取りこぼすと復帰できない。** 触っていないのに
  並びが変わる経路があった。押し下げで畳む・ボタンが離れていたら畳む・器が消えたら畳む、を足した
- **設定の版を読み込み後に揃えていなかった。** 中身は今の形なのに番号が古いまま書き戻るので、
  次に版を上げたときに移行済みか判定できない

### 仕組みに落としたもの

- **ドラッグの座標の原点を「行を並べている器」にした。** スクロール要素を原点にすると、
  フェーズ 4 で余白を 1 つ足しただけで掴む行と落ちる位置がずれる。
  器をずらしたテストを置いて、原点を変えると落ちるようにした
- **掴む行は DOM から取る。** ADR-0019 が DOM のヒットテストを禁じたのは**落とす先**の話で、
  掴む行は必ずポインタの下にあるので DOM にある。座標から逆算する必要が無い
- **`VirtualRows` から `overlay` を外した。** 仮想化の知識を使っていないうえ、`measure` と
  併用すると座標が合わない。挿入線は呼び出し側の器に置いた
- **`flatten` のメモ鍵を `Record<keyof FlattenOptions, string>` にした。** 引数を足したときに
  鍵の側を直し忘れると、「呼ばれているのに古い行が返る」形で壊れる
- **「コンソールが見えているか」の定義を 1 本にした** (`store/consoleActions.ts`)。
  印を立てる側と消す側が同じ判定を使う
- **一括フェッチの状態を触る入口を `store/results.ts` に揃えた** (`cancelBulkFetch`)
- **表示時間・件数・デバウンス・ペイン幅を、仕様の実値でテストに固定した。** 定数を
  相対的に参照するテストだけだと、値そのものを書き換えても緑になる
- **ADR-0012 の置き換えの注記を文書の先頭に移した。** 「ドラッグ並び替え」の節にしか
  掛かっておらず、`@dnd-kit/*` の「追加は承認済み」が生きたまま残っていた

### 見送ったもの

- **一括操作を「フェッチ 1 種類前提」から一般化する。** v1 の一括操作はフェッチだけ
  ([../adr/0007-v1-scope.md](../adr/0007-v1-scope.md))。2 種類目を足すときに、ストアを増やすのではなく
  種別を持たせる形に寄せる、という覚えだけ残す
- **`consoleOpen` を UI ストアからコンソールのストアへ移す。** 「見えているか」の定義は 1 本にしたので、
  いまの困りごとは消えている。常駐でウィンドウを隠す話が入るフェーズ 4 で判断する
  ([phase-4-polish.md](phase-4-polish.md) に移した)
- **検索中のシェブロンで折りたたみが変わること。** 見た目が変わらないのに保存状態が変わるが、
  これは [../specs/ui.md](../specs/ui.md) が「状態だけ変わる」と決めている振る舞い。
  テストで固定して、意図しない変更で壊れないようにした
